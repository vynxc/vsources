# Provider playback audit — 2026-09-26

**41 of 47 registered provider routes produced a stream that decoded eight seconds of video and audio.** Forty passed with ordinary TMDB configuration; MovieBox additionally required `MOVIEBOX_MOBILE_SIGNING_KEY`. Six remain unverified. The “one playable media from every provider” target is not yet complete.

This supersedes the earlier [lightweight liveness audit](2026-09-26.md) for playback claims. [Machine-readable results](2026-09-26-playback-results.json) preserve all selected attempts, timestamps, binary hashes, and sanitized codec evidence.

## What was verified

The [harness](../../scripts/verify_playback.py) resolves a fresh CLI result and runs FFmpeg with the stream’s playback headers. It decodes video and audio into the null muxer, scales video to 320 pixels wide, and requires exit 0, at least 24 frames, at least 7.8 seconds of output, and nonzero decoded audio. Every successful sample actually produced at least 190 frames. No full movie was saved.

Test decoder: `ffmpeg version n9.0.2 Copyright (c) 2000-2026 the FFmpeg developers`. HLS segments with misleading `.jpg` names are allowed, with network protocols limited to HTTP(S), TCP/TLS, crypto and data. Calls are bounded; requests to the same media host are serialized by the harness.

This proves short playback through each registered SDK route. Several providers share VidKing or other fallback backends, so 41 routes do not mean 41 independent upstream services. It does not prove whole-title playback, content identity, English audio/subtitle correctness, seeking, every alternative track, or every returned card. No proxy or FlareSolverr was configured. Signed media URLs and cookies are excluded from saved evidence; private FFmpeg logs remain under `/tmp/vsources-playback-*` and may expire.

## Six unresolved providers

| Provider | Observed blocker | Next useful step |
|---|---|---|
| `acermovies` | **Empty source responses.** Current api2 search and quality endpoints respond, but source requests return only fromCache:false. A returned Modpro link is parked. No playable result found across the sampled titles. | Recheck source resolution when its upstream links recover; changing the API hostname alone does not fix it. |
| `imdbplay` | **Cloudflare blocks token mint.** Raw WASM loading/decryption is repaired. The subsequent generate.php request to peregrinepalaver.space receives a real Cloudflare 403 block, including direct curl checks. | Retest from an allowed connection or a configured solver, then verify the token and media chain. |
| `nowhdtime` | **API timeouts; alternate hosts fail.** nhdapi.com times out in both SDK and curl. The live frontend’s VidNest alternative was researched; sampled backends returned 404/502 or GoodStream embeds blocked by Cloudflare. | Restore API access or find a genuinely playable alternate backend before adding a fallback. |
| `peckle` | **Missing caller cookie.** PECKLE_FEBBOX_COOKIE is absent. Anonymous metadata lookup works, but the authenticated quality response cannot be verified. The provider deliberately returns NotFound without its required cookie. | Configure the caller’s own FebBox ui= cookie and rerun Peckle. |
| `stellar` | **CDN 502.** The API returns signed HLS masters. Child playlists at cdn.reallyfast.ch repeatedly return HTTP 502 across sampled titles/variants, also reproduced with curl. | Retest after CDN recovery or from another working connection; do not permanently ban the host. |
| `vixsrc` | **Cloudflare challenge.** Site, API and playlist requests encounter real Cloudflare 403 challenges. The current signed-playlist extraction reference was found, but could not be validated from this connection. | Configure a working solver/connection, adapt the current signed-playlist path if required, and decode it. |

These are connection/configuration/service observations, not permanent provider bans. More titles and cards were tried during the earlier phase reports; the final all-provider run used up to two requested titles and two cards per title. A local FlareSolverr was not available, and the current account cannot access the Docker socket. No user FebBox cookie was supplied.

## Repairs made during verification

- Fixed false Cloudflare detection: passive `/cdn-cgi/.../jsd/` scripts on healthy pages and ordinary HTTP 429 responses no longer poison the challenge cache.
- Added raw binary request bodies and bounded binary response handling. CineJoy’s sealed POST was still a stub; IMDBPlay’s WASM was being decoded through lossy text.
- Updated ReAnime’s Svelte data/download flow, ZXCStream’s current encrypted API, VidZee’s current stream API and required Referer, and AniKage’s runtime relay discovery.
- Corrected AnimeZeY string-valued sizes, release-group/first-episode matching, and signature-host preservation. Removed unbounded media validation from AnimeZeY, AniKage and NikaStream.
- Preserved Nexabloom’s required Referer, honored explicit HLS hints for opaque URLs, and fixed a Unicode byte-offset panic in title enrichment.
- Accepted PlayIMDB’s string-valued status code. Added MovieBox’s optional mobile DASH flow with caller-supplied signing key and signed CDN cookies; excluded the legacy upgrade-notice clip.
- Fixed TUI/mpv header forwarding so multiple required headers survive, and configured HLS demuxing for media segments with unconventional suffixes.

## Configuration and reproduction

Supply `TMDB_API_KEY` or `TMDB_ACCESS_TOKEN` in the environment. For the verified MovieBox route, also provide the hex `MOVIEBOX_MOBILE_SIGNING_KEY`; the signing key is intentionally not bundled or persisted. An embedded caller can instead use `MovieBox::with_mobile_signing_key(Vec<u8>)`. For Peckle, supply the caller’s own `PECKLE_FEBBOX_COOKIE` containing `ui=...`.

```sh
cargo build -p vsources-cli
python3 scripts/verify_playback.py \
  --cases docs/audits/2026-09-26-playback-cases.json \
  --titles 2 --cards 2 --workers 2 \
  --logs /tmp/vsources-playback-rerun \
  --output /tmp/vsources-playback-rerun.jsonl
```

Use `--providers imdbplay,nowhdtime,peckle,stellar,vixsrc,acermovies` for unresolved routes, or `--providers moviebox --media 27205 --titles 1` for the configured mobile route. Series samples in the case file use S1E1. `--source-timeout` defaults to 35 seconds; the CLI process gets 40 seconds beyond that for metadata and orchestration. The harness supports the known series IDs listed in its `SERIES` set.

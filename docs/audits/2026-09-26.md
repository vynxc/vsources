# Live quality audit — 2026-09-26

The broad pass ran 47 providers against seven titles (329 cases), with six provider jobs at a time and a 35-second source budget. It used the new bounded media probe but the original extractor registry implementations. A second pass reran seven affected providers across all seven titles after implementing VidKing and EmbedResolver (49 cases). All requests originated from this machine.

These counts are provider cards, including duplicate URLs. “Alive” means the lightweight probe reached recognizable media; it does not certify every segment, encryption key, alternate audio track, subtitle or the complete film. Unknown cards remain eligible. External pages and known single-use Google download links are not consumed.

## Restored movie fallback

VidFast, VidKing and VidSrcSbs had returned Inception in 0 ms with no streams. The VidKing extractor was a stub that never matched or resolved anything. Its protocol implementation already existed in the provider crate; that implementation now lives in the extractor crate and is re-exported from its old path. A per-media cache coalesces fallback calls across distinct embed URLs.

A separate final CLI resolve restricted to VidFast + VidKing + VidSrcSbs returned **four unique Inception streams in 2.46 seconds**, including metadata and liveness checks. AnimeKai Frieren S1E1 returned two streams in 2.74 seconds. These are cold CLI wall times, not an A/B benchmark of concurrency settings; the default width remains six.

Netlio’s exact Inception data path returned HTTP 404 with both the SDK and curl. That establishes a missing catalog entry, not a dead provider. NowHDTime’s API timed out through the SDK (25 s) and curl (27 s, no response bytes); this remains an inconclusive service/network failure. The upstream source files use the same endpoints. No provider or host was removed.

## Actual coverage and remaining work

The previous claim of 38 completed extractors was incorrect. There are 36 host modules and 32 registry entries. Four modules remain stubs: `nuvio`, `vidsrcme`, `anipriv8`, `zxcstream`. VidKing and EmbedResolver were also stubs before this pass; both now have implementations and regression tests. The real VidKing fallback has live evidence above; EmbedResolver has offline fixture coverage and runs in the live registry, but a separate successful real embed sample has not been isolated for it.

VidSrcMe requires a WASM decryptor plus an IP-bound token/playback strategy. It cannot honestly be represented as a working direct extractor without implementing that flow. Nuvio, AniPriv8 and ZXCStream still need deliberate adaptation of the upstream proxy/metadata behavior. Not every host family has been live-verified independently.

The 47 registered providers match upstream source filenames after normalizing TwoDhive and NikaStream. Additional upstream classes are omitted under the earlier language policy: AnimesDigital, BollyFlix, CineFreak, CineHDPlus, DesiFlix, Eurostreaming, FourKHDHub, FourKHDHubOne, HDHub4uV2, HindMovie, HindMoviez, KMMovies, MeineCloud, MostraGuarda, MovieBlast, MovieLinkBD, MoviesDriveV2, MoviesHuntV2, Movix, Pantyflix, PersianStremio, UHDMovies, VegaMovies, VegaMoviesNew, VerHdLink. Several advertise English alongside Hindi, so filename counts alone do not establish complete English coverage. NuvioSource and the other unmatched files are infrastructure. No exclusions changed in this pass.

Provider-local legacy probes (notably AniKage, Netlio and NowHDTime) still predate the new gate and can suppress results before the engine sees them. Consolidating those decisions is follow-up work; the new central gate does not undo earlier provider filtering. Large-provider modularization and further Nuvio label/decoding consolidation also remain.
